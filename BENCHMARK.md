# Результаты бенчмарка производительности

Сравнение скорости трёх реализаций фильтрации треков AIS — **Python**, **Go**, **Rust**.
Замеряется реальное время выполнения процесса (чтение stdin → обработка → stdout).

## Окружение

| Параметр    | Значение |
|-------------|----------|
| Дата        | 2026-10-29 |
| CPU         | AMD Ryzen 9 7940HS w/ Radeon 780M Graphics (16 потоков) |
| ОС          | Linux amd64 |
| Python      | 3.12.3 (`.venv`) |
| Go          | go1.24.9 linux/amd64 |
| Rust        | rustc 1.98.1 / cargo 1.98.1 |
| Компиляция Go | `GOTOOLCHAIN=local go build -o ... .` |
| Сборка Rust   | `cargo build --release` |

Настройки фильтрации берутся из `.env` (`set -a && . ./.env && set +a`):
`SHAPEFILE=/opt/filter/restrict.shp`, `MAX_SPEED=20`, `DIFF_SPEED=15`.

## Методика

- Скрипт: [`benchmark.sh`](benchmark.sh).
- Каждая версия прогоняется N раз; измеряется реальное время через `date +%s%N`.
- Вывод программы направляется в `/dev/null` (замеряется только вычисление, без записи результата).
- Для быстрых языков (Go/Rust) число итераций увеличено в `FAST_SCALE` раз (по умолчанию 10),
  т.к. их времена в миллисекундах — так статистика устойчивее. Среднее считается отдельно для
  каждой версии, поэтому сравнение честное.
- Время сборки Go/Rust **не входит** в замер.

## Входные данные

| Файл | Судов | Точек | Размер |
|------|-------|-------|--------|
| `data/track-20250326.json` | 1 | 147 | ~23 КБ |
| `data/big-input.json` (синтетический) | 200 | 12000 | ~2.0 МБ |

> На маленьком входе значительная часть времени — накладные расходы на запуск процесса
> (загрузка Python-интерпретатора, shapefile, решётка). Для честного сравнения **вычислений**
> используется крупный вход `data/big-input.json`, где вычисления доминируют.

## Результат: маленький вход (`track-20250326.json`, 1 судно / 147 точек)

Параметры запуска: `FAST_SCALE=5 ./benchmark.sh 50 data/track-20250326.json`
(Python — 50 итераций, Go/Rust — 250).

| Версия | Среднее | Медиана | Минимум | Максимум | Ускорение |
|--------|---------|---------|---------|----------|-----------|
| Python | 137 мс  | 132 мс  | 126 мс  | 160 мс   | 1x |
| Go     | 7 мс    | 8 мс    | 6 мс    | 10 мс    | ~19x |
| Rust   | 2 мс    | 3 мс    | 2 мс    | 5 мс     | ~68x |

## Результат: большой вход (`big-input.json`, 200 судов / 12000 точек)

Параметры запуска: `FAST_SCALE=10 ./benchmark.sh 20 data/big-input.json`
(Python — 20 итераций, Go/Rust — 200).

| Версия | Среднее | Медиана | Минимум | Максимум | Ускорение |
|--------|---------|---------|---------|----------|-----------|
| Python | 594 мс  | 591 мс  | 578 мс  | 628 мс   | 1x |
| Go     | 38 мс   | 38 мс   | 35 мс   | 46 мс    | ~15x |
| Rust   | 9 мс    | 10 мс   | 8 мс    | 12 мс    | ~66x |

## Выводы

1. **Rust — самый быстрый**, затем **Go**, затем **Python**. На крупном входе
   Rust быстрее Python примерно в **66 раз**, Go — примерно в **15 раз**.
2. **Go и Rust побайтово идентичны** по выводу (проверено `cmp` на обоих входах).
3. На маленьком входе разрыв между Go (7 мс) и Rust (2 мс) частично обусловлен
   накладными расходами на запуск процесса; на крупном входе (вычисления доминируют)
   разрыв между Go (38 мс) и Rust (9 мс) показывает, что **сама Rust-реализация
   эффективнее** по вычислительной части.
4. Результаты носят ориентировочный характер и зависят от окружения; для воспроизведения
   достаточно перезапустить `benchmark.sh`.

## Как воспроизвести
