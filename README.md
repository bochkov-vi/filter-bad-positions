# Фильтрация треков AIS (MCC / filter)

Сервис отбраковывает «аномальные» точки треков судов (AIS-данные): точки в запретных
зонах, точки с нереалистичной скоростью и «скачки» координат. На вход принимается JSON
с треками, на выходе — очищенный JSON.

Реализован на трёх языках (Python, Go, Rust). Логика, настройки и формат вывода
идентичны, результат **побайтово совпадает** между версиями Go и Rust.
Все три версии берут настройки из переменных окружения ОС (см. `.env`).

## Настройки: переменные окружения ОС (`.env`)

Программы (Python, Go, Rust) читают параметры из переменных **окружения ОС**:

- **Python** — `os.environ.get(...)`
- **Go** — `os.Getenv(...)`
- **Rust** — `std::env::var(...)`

Если переменная не задана — используются значения по умолчанию (захардкожены в коде).

### Файл `.env`

Файл `.env` в корне содержит те же параметры для удобной загрузки в окружение
(это классический формат `ключ=значение`):

```env
# Путь к shapefile с запретными (аномальными) зонами
SHAPEFILE=/opt/filter/restrict.shp

# Максимальная допустимая скорость судна, узлы
MAX_SPEED=20

# Допустимая разница между расчётной скоростью и скоростью по данным терминала, узлы
DIFF_SPEED=15
```

> `.env` **игнорируется git** (см. `.gitignore`). Шаблон с теми же значениями — файл
> [`.env.example`](.env.example). Чтобы создать локальный `.env`, скопируйте шаблон:
> ```bash
> cp .env.example .env
> ```

> `.env` **не читается автоматически** программами — он лишь удобный способ
> подготовить переменные окружения. Загрузите его в окружение перед запуском:
> ```bash
> set -a && . ./.env && set +a
> ```
> Либо экспортируйте значения вручную:
> ```bash
> export MAX_SPEED=20 DIFF_SPEED=15 SHAPEFILE=/opt/filter/restrict.shp
> ```

### Параметры фильтрации

| Параметр     | Значение (по умолчанию) | Описание                                               |
|--------------|-------------------------|--------------------------------------------------------|
| `MAX_SPEED`  | `20`                    | максимальная допустимая скорость, узлы                  |
| `DIFF_SPEED` | `15`                    | допустимая разница между расчётной и терминальной скоростью |
| `SHAPEFILE`  | `/opt/filter/restrict.shp` | путь к shapefile с зонами                           |

> Все три версии (Python, Go, Rust) используют одинаковые значения из переменных
> окружения (включая `DIFF_SPEED = 15`). Это гарантирует идентичный результат фильтрации.

## Запуск

Входной JSON подаётся в stdin, результат — в stdout.

Сначала подготовьте переменные окружения (однократно в текущей сессии):
```bash
cd /home/bochkov/projects/MCC/filter
set -a && . ./.env && set +a
```

### Go
```bash
cd go
GOTOOLCHAIN=local go build -o track-filtering .
./track-filtering < ../data/track-20250326.json
```
Замечание: `GOTOOLCHAIN=local` гарантирует сборку установленным локальным Go-инструментом
(иначе переменная `GOTOOLCHAIN` в окружении может потребовать несуществующую версию, e.g. `go1.26.4`).
Бинарник читает shapefile по пути из переменной `SHAPEFILE`.
Для работы скопируйте данные в `/opt/filter/`:
```bash
mkdir -p /opt/filter && cp data/restrict.* /opt/filter/
```

### Python
```bash
# установить зависимости (один раз)
../.venv/bin/pip install -r python/requirements.txt   # или: pip install -r requirements.txt

cd python
../.venv/bin/python track_filtering.py < ../data/track-20250326.json
```
Замечание: Python-версия берёт `SHAPEFILE`, `MAX_SPEED` и `DIFF_SPEED` из переменных окружения.

### Rust
```bash
cd rust
cargo build --release
./target/release/track-filtering-rust < ../data/track-20250326.json
```
Замечание: `SHAPEFILE`, `MAX_SPEED` и `DIFF_SPEED` берутся из переменных окружения
(тот же путь, что и в Go).

## Проверка идентичности Go и Rust

```bash
# эталон (Go)
cd go && GOTOOLCHAIN=local go build -o /tmp/track-filtering-go . && /tmp/track-filtering-go < ../data/track-20250326.json > /tmp/go.json
# Rust
cd rust && cargo build --release && ./target/release/track-filtering-rust < ../data/track-20250326.json > /tmp/rust.json
cmp /tmp/go.json /tmp/rust.json && echo "BYTE-IDENTICAL"
```

## Производительность (бенчмарк)

В корне есть скрипт [`benchmark.sh`](benchmark.sh), который сравнивает скорость трёх
реализаций на одном и том же входе. Он собирает Go и Rust (время сборки не входит в замер),
прогоняет каждую версию несколько раз, измеряет реальное время выполнения (чтение stdin
→ обработка → stdout) и выводит среднее/медиану/минимум/максимум + ускорение относительно Python.

Подробный отчёт с результатами: [`BENCHMARK.md`](BENCHMARK.md).

```bash
# базовая настройка итераций (Python=100; Go/Rust=1000)
./benchmark.sh

# своё число итераций и свой входной файл
./benchmark.sh 50 data/big-input.json

# масштаб числа итераций для быстрых языков (Go/Rust по умолчанию x10 от Python)
FAST_SCALE=10 ./benchmark.sh 10 data/big-input.json
```

Параметры:
- `ITERATIONS` — базовое число прогонов для Python (по умолчанию 100).
- `INPUT_FILE` — входной JSON (по умолчанию `data/track-20250326.json`).
- `FAST_SCALE` (переменная окружения) — во сколько раз быстрые языки (Go/Rust) прогоняются
  чаще Python (по умолчанию 10), чтобы их миллисекундные времена были стабильными.

Скрипт сам загружает `.env` (`set -a && . ./.env && set +a`) и запускает все три версии.
Вход `data/big-input.json` — синтетический (200 судов, 12000 точек), генерируется скриптом и **не
коммитится** (добавлен в `.gitignore`). Пример результатов на `data/big-input.json`:

| Версия | Среднее время | Ускорение относительно Python |
|--------|--------------|-------------------------------|
| Python | 625 мс       | 1x                            |
| Go     | 38 мс        | ~16x                          |
| Rust   | 9 мс         | ~69x                          |

> Замер производится как реальное время всего процесса, включая запуск, загрузку shapefile
> и вывод. На маленьком входе (`track-20250326.json`, 1 судно/147 точек) значительная часть
> времени — накладные расходы на старт процесса, поэтому для честного сравнения вычислений
> используйте крупный вход (`data/big-input.json`).
